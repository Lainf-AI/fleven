    Execução¶

    O Fleven segue o padrão de apps do Flower e pode ser executado de três formas, do mais simples ao mais próximo de um cenário real.

    Método 1: Simulação Local¶

    A forma mais fácil de começar. Tudo roda na mesma máquina usando atores Ray em paralelo, sem necessidade de configurar servidores.

    flwr run . --stream

    Federações (Flower 1.31+)

    A partir do Flower 1.31, a configuração de conexão das federações saiu do pyproject.toml e fica em .flwr/config.toml. O número de clientes por grupo (num_supernodes) vai por run via --federation-config (chave com underscore), que o fleven run passa automaticamente. Para o flwr run . puro usar a config versionada, aponte o FLWR_HOME para a pasta do projeto antes de rodar: 

    $env:FLWR_HOME = "$PWD\.flwr"

    As configurações da aplicação (modelo, hiperparâmetros, features) vêm do pyproject.toml. Para ajustar parâmetros sem editar o arquivo:

    flwr run . --run-config "rounds=5 learning-rate=1e-4 prediction-length=10" --stream

    Método 2: Deployment Local¶

    Simula um cenário mais real, com o servidor (SuperLink) e os clientes (SuperNodes) rodando em processos separados na mesma máquina. Útil para testar a comunicação antes de ir para hardware real.

    Primeiro ajuste o caminho dos dados no pyproject.toml:

    [tool.flwr.app.config]
data-base-path = "C:/client/fleven/data/G01_HEV_18L_3000"

    No Terminal 1:

    flower-superlink --insecure

    Terminal 2, 3, …, N - para cada cliente, abra um terminal e execute, alterando o valor V de --clientappio-api-address e o id X de partition-id:

    flower-supernode --insecure \
  --superlink 127.0.0.1:9092 \
  --clientappio-api-address 127.0.0.1:909V \
  --node-config "partition-id=X"

    No terminal final (aponte FLWR_HOME para a config versionada em .flwr/, senão o flwr run não encontra a federação fleven-deployment):

    export FLWR_HOME="$PWD/.flwr"   # PowerShell: $env:FLWR_HOME = "$PWD\.flwr"
flwr run . fleven-deployment --stream

    Para ver os nós conectados:

    flwr ls fleven-deployment

    Método 3: Modo Híbrido com Docker¶

    Seu PC age como SuperLink (servidor), enquanto containers Docker simulam os SuperNodes, como se fossem Raspberry Pis embarcados nos veículos. Cada container recebe apenas os dados do seu próprio cliente.

    docker-compose -f docker/docker-compose.yml build

    Clientes em containers Docker, sem certificados de autenticação:

    # Inicie o SuperLink no seu PC
flower-superlink --insecure

# Inicie os containers Docker (outro terminal)
docker-compose -f docker/docker-compose.yml up -d

# Aponte FLWR_HOME para .flwr/ (onde vivem as federações)
export FLWR_HOME="$PWD/.flwr"

# Execute o treinamento federado
flwr run . fleven-deployment --stream

    O Flower 1.31 tem dois mecanismos independentes: (1) TLS (sempre) criptografa o canal e o SuperNode verifica o SuperLink pela CA, de uma via; (2) autenticação de nó (opcional) usa par de chaves EC por SuperNode. Primeiro gere as credenciais:

    pip install cryptography
python docker/generate_certificates.py

    Inicie o SuperLink com TLS e suba os containers:

    flower-superlink \
  --ssl-ca-certfile certificates/ca-cert.pem \
  --ssl-certfile certificates/server-cert.pem \
  --ssl-keyfile certificates/server-key.pem

TLS_ENABLED=true docker-compose -f docker/docker-compose.yml up -d

export FLWR_HOME="$PWD/.flwr"
flwr run . fleven-deployment-tls --stream

    Veja o guia de Deploy com Docker para instruções detalhadas.

    Rastreamento com MLflow¶

    O Fleven usa SQLite como backend de tracking (padrão MLflow 3.x): todas as métricas, parâmetros e metadados ficam em um único mlflow.db na raiz do projeto.

    mlflow ui

    Acesse http://127.0.0.1:5000 para ver os resultados.
