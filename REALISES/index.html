    Migração Flower 1.22 -> 1.31¶

    Registro das mudanças feitas para migrar o Fleven do Flower 1.22.0 para o 1.31.0. O Flower andou 9 versões minor nesse intervalo, então várias coisas mudaram de lugar ou de formato, mas o núcleo do Fleven (treino, agregação, modelo) seguiu compatível.

    Dependências¶

    • flwr 1.22.0 -> 1.31.0 (base e extra dev).
    • Python 3.10 -> 3.11: a 1.31 dropou o suporte ao 3.10. A imagem Docker do cliente passou de python:3.10-slim para python:3.11-slim.
    • PyTorch continua CPU-only no cliente (sem os pacotes CUDA).

    API do Flower (sem mudança no código)¶

    • Os imports do server.py e client.py já usavam os caminhos novos (flwr.app, flwr.serverapp, flwr.clientapp), então a relocação de módulos da 1.31 não afetou o projeto.
    • O padrão de decorators (@app.train(), @app.evaluate(), @app.main()) e os records (ArrayRecord, MetricRecord, RecordDict, Message, Context) seguem iguais.
    • Os construtores das estratégias adaptativas (FedAdam, FedYogi, FedAdagrad) mantêm os mesmos parâmetros que o server.py passa (eta, beta_1, beta_2, tau, fraction_train, min_train_nodes, etc.). Confirmado na doc oficial.

    Federações e config de simulação¶

    • A config de conexão das federações saiu do pyproject.toml e foi para o arquivo do Flower (.flwr/config.toml). Versionamos esse arquivo no repositório e o lemos via FLWR_HOME apontando para ./.flwr, recuperando a portabilidade.
    • O estilo options. (ex.: options.num-supernodes no config) foi deprecado na 1.28. O número de clientes agora vai por run via --federation-config "num_supernodes=N" (chave com underscore, não hífen).
    • As federações por grupo (g01-g05) foram consolidadas numa única local-simulation. O run_experiments.py passa o num_supernodes de cada grupo por --federation-config.
    • O run_experiments.py define FLWR_HOME automaticamente (via os.environ.setdefault), então o fleven run usa a config versionada sem configuração manual.

    Comportamento de execução¶

    • Na 1.31, o flwr run . puro apenas inicia o run e volta ao prompt; o treino roda em segundo plano. Use --stream para acompanhar e esperar terminar.
    • O run_experiments.py passou a usar --stream. Sem isso, o evaluate rodava antes do treino terminar e lia métricas velhas (bug silencioso).

    MLflow¶

    • log_model adaptado para a API do MLflow 3.x: name= no lugar de artifact_path, e serialization_format="pickle" (o padrão pt2 exige input_example).
    • O push_to_dagshub foi validado contra o MLflow novo (construtores de Metric/Param e copy_run continuam funcionando).

    Segurança e autenticação de nó¶

    • O CSV estático de chaves (--auth-list-public-keys) foi deprecado na 1.23. O cadastro de nós passou a ser dinâmico via CLI (flwr supernode register / unregister / list, com o SuperLink subindo com --enable-supernode-auth), sem reiniciar o servidor.
    • Modelo confirmado na doc: TLS é de servidor (mão única), e a autenticação de cliente é por par de chaves EC, não por certificado X.509. O generate_certificates.py foi atualizado para gerar essas chaves EC (P-384, OpenSSH) por nó em vez do certificado por cliente vestigial, e o entrypoint Docker liga a autenticação de nó via NODE_AUTH_ENABLED (opt-in, exige TLS).

    Correções aproveitadas na validação¶

    • explore_data.py: coluna 100% NaN (ex.: feature sem dados num grupo) deixou de quebrar a geração do PDF.
    • server.py: o log das métricas finais resolve metrics-base-path vazio para <raiz>/metrics, igual ao cliente, corrigindo o final_predictions.json não encontrado.

    Windows¶

    • O WinError 1114 (DLL do PyTorch com o Ray) não ocorre mais na 1.31. O workaround do sitecustomize.py deixou de ser necessário.
    • O ruído do Ray (access violation, stack traces do raylet) na simulação no Windows é inofensivo (0 failures) e só existe na simulação, não no deployment.

    Documentação atualizada¶

    • README.md, docs/EXPERIMENTS.md, docs/LAINF-DEPLOY.md: referências ao formato antigo ([tool.flwr.federations] no pyproject) trocadas pelo .flwr/config.toml e pelo --federation-config.
    • docs/FLEVENCLIENT_PRODUCAO.md: seção de segurança reescrita para o modelo da 1.31 (autenticação de nó por CLI).
